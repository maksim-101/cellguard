<objective>
Fix a data-fidelity bug and add a new per-event metadata flag, both following the existing boolean-flag pattern already used for `isExpensive` / `isConstrained`.

Purpose: The probe-path events — especially `silentFailure`, the core Apple-evidence signal — currently hardcode `isExpensive`/`isConstrained` to false, so Low Data Mode is always misrecorded as OFF on the most evidence-critical events. Separately, Low Power Mode is the single most likely Apple-engineering deflection for background cellular-drop evidence ("that's just Low Power Mode working as designed"). Recording Low Power Mode per-event lets the user prove drops occurred with it OFF.

Output: Live `isExpensive`/`isConstrained` flags on all probe-path events; a new `lowPowerMode: Bool` field on `ConnectivityEvent` populated everywhere, surfaced in the detail UI, and carried in JSON export.
</objective>
